# Защита доступа Vexa — шаг 1

Пароль необязателен, содержит 1–1024 символа Юникода. Пробелы сохраняются,
требований к составу нет. Пустая строка не устанавливает пароль: для отказа
от защиты используется отдельная кнопка.

Argon2id v1.3: 19 MiB памяти, 2 прохода, 1 линия, случайная соль 16 байт,
результат 32 байта в формате PHC. Исходники Argon2 включены в сборку.

При установке и смене пароля создаётся новый случайный код восстановления
на 128 бит. Сохраняется только SHA-256 от строки с отдельной областью применения
`vexa/access-recovery/v1/` и нормализованного кода. Старый код перестаёт работать
после смены пароля. Смена и отключение требуют текущий пароль или код.

После пяти ошибок: 30, 60, 120, 240, 480, затем 900 секунд между попытками.
Счётчик и срок ожидания сохраняются; перезапуск не сбрасывает их.
Успешная проверка сбрасывает счётчик. После записи выполняется чтение
для проверки сохранения. При ошибке хранилища доступ не предоставляется.

Windows: Диспетчер учётных данных, системные уведомления блокировки и сна.
Linux: Secret Service через `secret-tool`; нужен запущенный и разблокированный
GNOME Keyring, KWallet с поддержкой Secret Service либо совместимый сервис.
Для уведомлений сна и блокировки используется logind через Qt DBus. Монитор
создаётся только при доступном хранилище: без него пароль не устанавливается и
монитор не запускается.
Если текущий процесс не найден в logind, уведомления сна и блокировки не
подключаются и не блокируют приложение; таймер бездействия остаётся.
Автоблокировка наступает после десяти минут без пользовательского ввода.
Переключение на другое приложение само по себе не блокирует Vexa.

Реализованы системные хранилища настольных Windows/Linux. На остальных
платформах установка пароля завершается сообщением о недоступности хранилища;
незащищённый режим остаётся доступен. Небезопасной замены хранилища нет.

Контроллер финансов и его база создаются после допуска. Блокировка скрывает
финансовые окна, уничтожает их, отменяет запросы и закрывает базу. При входе
создаётся новый контроллер. Смена защиты также завершает текущий сеанс.
Файл `access.lock` отмечает, что хранилище защиты уже использовалось; отключение
пароля не удаляет этот маркер. Пароль и проверочные записи не попадают в базу
и резервные копии. Один экземпляр приложения владеет каталогом данных.

Это блокировка доступа через приложение, а не шифрование файла базы.
Шифрование базы и переносимый защищённый архив относятся к следующим шагам.

Проверка алгоритма и хранения: цель CMake `PasswordLockTest`.
