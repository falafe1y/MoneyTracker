# Переносимые копии Vexa — шаг 3

Патч накладывается после шага 2. Интерфейс предназначен для Windows.

По умолчанию экспорт создаёт `.vexabackup` с отдельным паролем: 12–1024
символа Unicode, не более 4096 байт UTF-8. Пробелы и регистр сохраняются.
Пароль входа в приложение и ключ Windows в файл не включаются.
Копию можно восстановить на другом компьютере, зная только её пароль.
Незашифрованный экспорт `.sqlite3` выбирается явно и сопровождается предупреждением.

## Формат

Заголовок — 16 байт: `VEXABACKUP`, пять нулевых байт, затем `01`.
Далее идёт база SQLCipher профиля 4: AES-256-CBC, страницы 4096 байт,
HMAC-SHA512, PBKDF2-HMAC-SHA512 с 256000 итерациями. Пароль передаётся
как UTF-8 с фиксированным префиксом `vexa-portable-v1:`; строка вида
`x'…'` не может переключить обработку на необработанный ключ.
Таблица `vexa_portable_backup` внутри защищённой базы содержит версию
профиля, дату создания и версию приложения. Максимальный размер файла — 2 ГиБ.

Экспорт переносит всю базу, включая заметки, криптовалюты и инвестиции.
Промежуточные базы защищены случайными ключами. Готовый файл публикуется
атомарно после проверки целостности; ошибка не заменяет существующий файл.

## Восстановление

Выбранный файл копируется во временный каталог. Проверяются заголовок,
размер, криптографическая целостность, целостность SQLite, схема после
миграций и внешние ключи. Затем показывается предварительный просмотр.
Подготовленная копия привязана к разблокированному сеансу и действительна
10 минут. Блокировка, отмена или повторный выбор сбрасывают её.

После подтверждения соединения закрываются. Текущая база сохраняется
в `backups/before-restore-*.sqlite3`, новая база получает текущую защиту
устройства, заменяет рабочую базу и проверяется. При ошибке итоговой
проверки выполняется откат. После успеха приложение перезапускается.
Пароль копии не становится паролем приложения или ключом рабочей базы.

Если рабочая база не открывается, копию можно выбрать на экране ошибки.
Исходная база и её журналы сохраняются в `recovery-original-*`. Для
зашифрованной рабочей базы при необходимости создаётся и проверяется
новый ключ Windows перед установкой проверенной копии.

Старые открытые копии также принимаются. Старые зашифрованные `.sqlite3`
требуют исходный ключ устройства; неперенесённый непустой WAL не допускается.

## Проверка

Автотест `PortableBackupTest` проверяет перенос между разными ключами,
все сочетания защиты источника и назначения, Unicode-пароли, неверный
пароль, повреждение и усечение файла, неизвестную схему, внешние ключи,
отмену, блокировку сеанса, сохранение оригиналов при восстановлении
и независимость подготовленной копии от последующего изменения файла.

Проверка на Windows после сборки:

1. Создать операции и заметку, экспортировать защищённую копию.
2. Восстановить её в отдельном профиле Windows: неверный пароль должен
   отклоняться, правильный — открывать предварительный просмотр.
3. Подтвердить восстановление, дождаться перезапуска, проверить данные.
4. Повторить для открытой и зашифрованной рабочей базы: её выбранная
   защита должна сохраняться, а предыдущие данные — оставаться в `backups`.
5. Повредить отдельный экземпляр файла копии: импорт должен отклонить его,
   сохранив рабочую базу без изменений.

Автотесты выполнены в среде Qt/SQLCipher. Нативная сборка Windows,
Диспетчер учётных данных и системные диалоги требуют проверки на Windows.
