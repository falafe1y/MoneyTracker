# Шифрование базы Vexa — шаг 2

Накладывается после первого патча. Интерфейс управления и хранилище ключа
реализованы для Windows. SQLCipher 4.14.0 включён в исходники и собирается
вместе с приложением. Обычный драйвер Qt QSQLITE не используется для рабочей базы.
Адаптер использует только общедоступный интерфейс Qt SQL.

## Сборка Windows

Нужен OpenSSL 3 с заголовками и статической библиотекой для выбранного компилятора.
Например, для Qt MinGW 64 и окружения MSYS2 MINGW64:

```
pacman -S mingw-w64-x86_64-openssl
```

В параметрах CMake проекта Qt Creator:

```
-DOPENSSL_ROOT_DIR=C:/msys64/mingw64
```

Для UCRT64 или MSVC требуется соответствующая сборка OpenSSL, а не смешение
инструментариев. `OpenSSL::Crypto` связывается статически. CMake сообщает об
отсутствующей зависимости при настройке; отключённой заменой шифрования
ошибка не подменяется. Дополнительный плагин SQLCipher для Qt не нужен.

## Механика

SQLCipher: AES-256-CBC, HMAC-SHA512, страницы 4096 байт. Для локальной базы
используется случайный ключ на 32 байта через интерфейс необработанного ключа.
Он хранится отдельно от пароля входа, в Диспетчере учётных данных Windows.
Перед использованием нового ключа проверяется его запись обратным чтением.
При открытии существующей нечитаемой базы новый ключ не создаётся.

Преобразование останавливает финансовый интерфейс и закрывает соединения.
Затем создаёт и проверяет новую базу, создаёт копию для отката, заменяет файл
на том же диске и проверяет результат. При подтверждённой ошибке проверки
выполняется откат. После успеха приложение перезапускается.

При включении копия для отката уже зашифрована новым сохранённым ключом;
после успешной операции она удаляется. При отключении сохраняется предыдущая
зашифрованная копия в `backups`. Ключ после отключения не удаляется.
Временные SQL-данные хранятся в памяти; страницы журнала защищены SQLCipher.
При запуске удаляются только оставшиеся временные каталоги преобразования,
а не опубликованные копии для восстановления.

Маркер `.encrypted` хранит ожидаемую защиту при отсутствии основного файла.
Для существующей базы состояние определяется проверкой файла; оставшийся
ключ не превращает открытую базу в зашифрованную автоматически.

Обычная резервная копия сохраняет шифрование источника. Восстановление
принимает открытые копии и зашифрованные копии с сохранённым ключом этого
устройства, не меняя текущую защиту базы. Такие зашифрованные копии ещё
не являются переносимым архивом: формат `.vexabackup` относится к шагу 3.
Пароль входа и код его восстановления не заменяют ключ базы.

Проверки CMake: `DatabaseEncryptionTest`, а также существующие проверки
репозитория и восстановления. На пользовательских данных проверка не выполняется.
